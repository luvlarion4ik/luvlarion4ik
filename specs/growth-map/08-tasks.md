# 08. Задачи для агентов

Оркестратор — Sonnet. Исполнители — Sonnet и Haiku. Opus не нужен: все решения уже приняты в 01–07. Если агент упирается в противоречие между файлами ТЗ, он не выбирает сам, а останавливается и пишет владельцу, какие строки противоречат друг другу.

## Общие правила для каждого агента

1. Прочитать README.md и 01-product-ux.md целиком, затем свой файл ТЗ. Чужие файлы — только нужные разделы.
2. Работать в отдельной ветке от `main`: `growth-map/<номер задачи>-<коротко>`. Один PR на задачу, в описании — номер задачи и чек-лист приёмки с отметками.
3. Никаких npm-зависимостей и сборщиков на сайте. Ванильный JS, классические скрипты, IIFE, `window.DevlarionGM`.
4. Тексты интерфейса — только из 02-copy.md. Новую строку добавить в 02-copy.md в том же PR.
5. Перед PR: `npm run build`, `npm run check`, `npm run test:gm` (когда появится) — всё зелёное. Сгенерированный `docs/` коммитится вместе с исходниками.
6. Ничего не публиковать, не пушить в `main` и не трогать секреты. PR создаёт агент, мержит владелец.

## Граф задач

```
T1 каталог ──┬── T2 движок ──┬── T4 панель ──┐
T3 иконки ───┤               │               ├── T6 приложение и интеграция ── T7 кабинет и тизер ── T8 проверка
             └── T5 холст ───┘               │
                                              (T4 и T5 параллельно)
T9 ИИ-воркер — только после выхода этапа 1 в продакшен
```

## T1. Каталог (Sonnet)

Файлы: `docs/assets/growth-map/gm-catalog.js`, `gm-copy.js`.
- Перенести 03-catalog.md в данные. Написать английские тексты для всех блоков, сфер, подкатегорий и подсказок.
- Составить `keywords` для каждой подкатегории, источника, способа приёма заявок, оплаты, боли и желания (RU + EN корни, 6–15 штук).
- `gm-copy.js` — все строки из 02-copy.md с теми же ключами.

Приёмка: скрипт загружается в `vm` без ошибок; у каждого блока есть `stage`, `icon`, `title.ru/en`, `benefit.ru/en`, `fx`, `tier`; все id уникальны; все `next` и `replaces` ссылаются на существующие блоки; все `service` есть в `estimator` из `content/pricing.mjs` или равны `null`; в `gm-copy.js` нет ключей без английского перевода.

## T2. Движок и тесты (Sonnet)

Файлы: `gm-engine.js`, `scripts/test-growth-map.mjs`, `scripts/fixtures/growth-map/*.json`, `package.json` (скрипт `test:gm`), `.github/workflows/check.yml`.
- Всё из 04-engine.md, включая `parseText`.
- Все 11 групп проверок из 06-integration.md, раздел 8.

Приёмка: `npm run test:gm` зелёный; в README задачи — таблица по 5 фикстурам: число узлов в каждом варианте, выручка, прирост, цена, окупаемость. Владелец посмотрит на неё глазами: цифры должны выглядеть щедро, но правдоподобно.

## T3. Иконки (Haiku)

Файл: `gm-icons.js`. Список нужных иконок собрать из `gm-catalog.js` (поле `icon` блоков и сфер) и 05-canvas.md, раздел 8. Стиль как у `docs/assets/icons/*.svg`. Бренды — из Simple Icons.

Приёмка: для каждого `icon` из каталога есть ключ; каждая строка — валидный `<svg>` с `viewBox="0 0 24 24"`; страница-проверка `scripts/fixtures/growth-map/icons.html` (не попадает в `docs/`) показывает все иконки сеткой с подписями; скриншот сетки в PR.

## T4. Панель (Sonnet)

Файлы: `gm-panel.js`, часть `growth-map.css` (панель, бриф, библиотека, инспектор, сравнение, нижняя панель), разметка панели в `content/growth-map.mjs`.
- Экран выбора режима, бриф по шагам, режим «своими словами» с подсветкой распознанных полей, библиотека с поиском и перетаскиванием (отдаёт холсту событие `gm:drop`), инспектор, сравнение с карточками разницы, гарантиями и отзывами из `gm-config`, нижняя панель экономики со счётчиками.
- Мобильная шторка из 01-product-ux.md, раздел 9.

Приёмка: все поля брифа работают с клавиатуры; шаги не скроллятся на 1440×900 (кроме шага 4); суммы меняются при смене валюты на сайте; пустые `guarantees` и `reviews` не дают пустых блоков.

## T5. Холст (Sonnet)

Файлы: `gm-canvas.js`, часть `growth-map.css` (сцена, узлы, связи, анимации).
- Всё из 05-canvas.md. Холст получает вариант и экономику, отдаёт изменения событием `gm:change` с новым `{ nodes, edges }`.
- Временная страница для разработки `scripts/fixtures/growth-map/canvas.html` рендерит вариант `boost` из фикстуры `barber.json`.

Приёмка: 60 fps при перетаскивании на схеме из 30 узлов (запись Performance в Chrome, скриншот в PR); морфинг между четырьмя вариантами без «прыжков»; «Объём» включается и выключается; при `prefers-reduced-motion` нет частиц и наклонов; управление с клавиатуры по таблице из раздела 3; «Показать списком» работает.

## T6. Приложение и интеграция (Sonnet)

Файлы: `gm-app.js`, `content/growth-map.mjs` (сборка страницы целиком), `scripts/build.mjs`, `content/site.json`, `scripts/validate-site.mjs`, `scripts/admin.*`.
- Состояние документа, история отмены (50 шагов на вариант), автосохранение, `#open=`, `#map=`, импорт и экспорт, «С возвращением», Telegram, цели аналитики, приватность.
- Всё из 06-integration.md, разделы 1–7 и 9.

Приёмка: полный сценарий от выбора режима до черновика в Telegram проходит на `/growth-map/` и `/ru/growth-map/`; ссылка `#map=` открывается в другом браузере и даёт ту же карту; файл скачивается и открывается обратно; `npm run check` зелёный.

## T7. Кабинет и тизер (Haiku)

Файлы: `content/portal.mjs`, `docs/assets/portal.js`, `docs/assets/portal.css`, `docs/assets/home.css`, `content/growth-map.mjs` (`renderGrowthMapTeaser`).

Приёмка: сохранённая карта видна в кабинете, открывается и удаляется; тизер выглядит на 375, 768 и 1440 px во всех четырёх темах; скриншоты в PR.

## T8. Проверка (Sonnet, отдельный агент, не автор кода)

Прогнать чек-лист ниже, приложить скриншоты, завести замечания в PR. Код правит не проверяющий, а автор соответствующей задачи.

### Чек-лист ручной проверки

Браузеры: Chrome и Safari на macOS, Safari на iPhone (или эмулятор 375×812), Firefox — только базовый сценарий.

- [ ] Пять фикстур, введённые руками через бриф, дают те же варианты, что в тестах.
- [ ] Три примера текста дают ожидаемый разбор, распознанные поля подсвечены.
- [ ] Сцена анализа длится около 5 с, «Пропустить» работает.
- [ ] После анализа открыт «Ускорение» с меткой «Рекомендуем», вкладка «Сравнение».
- [ ] В «Как сейчас» видны красные маркеры потерь и подпись «Клиенты не возвращаются».
- [ ] Переключение 1→2→3→4 и обратно: морфинг плавный, новые блоки помечены, счётчики накручиваются.
- [ ] Перетаскивание узла, создание и удаление связи, добавление блока из библиотеки (перетаскиванием и кликом), удаление блока, отмена и повтор.
- [ ] Узел без связей мерцает, экономика учитывает его вполсилы.
- [ ] Инспектор: пояснение, эффект в деньгах, настройки (платёжный сервис, CRM), «Заменить на…».
- [ ] «Объём»: переход, вращение, выход по Esc.
- [ ] Валюта: смена на USD и KZT пересчитывает все суммы на карте и в сравнении.
- [ ] Темы: Авто, Медь, Тёмно-синяя, Шалфей. Сцена тёмная во всех, вокруг — тема сайта.
- [ ] Мобильная версия: пан, щипок, долгое нажатие для перемещения, шторка в трёх положениях, бриф полноэкранными шагами.
- [ ] Перезагрузка страницы: «С возвращением», карта на месте.
- [ ] Ссылка: копируется, открывается в приватном окне.
- [ ] Скачать и открыть файл; битый файл даёт понятную ошибку.
- [ ] Кабинет: карта видна, открывается, удаляется.
- [ ] Telegram: черновик открывается, текст читается, ссылка внутри работает.
- [ ] Safari в приватном режиме: плашка про хранилище, карта работает.
- [ ] `prefers-reduced-motion`: никакого движения, всё доступно.
- [ ] Клавиатура: весь сценарий без мыши, фокус всегда виден.
- [ ] VoiceOver: «Показать списком» читается по этапам.
- [ ] Lighthouse на `/ru/growth-map/`: доступность без ошибок уровня serious, консоль чистая.
- [ ] Тексты: ни одного слова из запретного списка 02-copy.md, ни одной строки без перевода, ни одного `undefined` или `{`.

Скопировать в новую сессию Claude Code на модели Sonnet в корне репозитория:

```text
Реализуй «Карту роста» по ТЗ в specs/growth-map/. Начни с README.md и 08-tasks.md.
Ты оркестратор: запускай задачи T1–T8 субагентами на тех моделях, что указаны в 08-tasks.md (Sonnet или Haiku), соблюдая граф зависимостей; T4 и T5 запускай параллельно. T9 не трогай.
Каждый субагент работает в своей ветке и открывает PR в main. Перед следующей задачей проверь, что PR предыдущей прошёл приёмку из 08-tasks.md и npm run check зелёный.
Если ТЗ противоречит само себе или коду репозитория, остановись и спроси меня, не выбирай сам.
В конце пришли список PR, таблицу цифр по пяти фикстурам и результат чек-листа T8 со скриншотами.
```
