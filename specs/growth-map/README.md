# «Карта роста» — техническое задание

Интерактивный конструктор на сайте Devlarion. Владелец бизнеса рассказывает о своём деле, а сайт за минуту рисует схему: откуда приходят клиенты, где теряются заявки, как проходит оплата и что возвращает людей за повторной покупкой. Схема строится в трёх вариантах («Фундамент», «Ускорение», «Автопилот»), рядом с каждым видно, сколько денег он приносит и сколько бизнес теряет, если выбрать вариант попроще. Любой блок можно перетащить, удалить или добавить из библиотеки. Готовую карту можно скачать, сохранить в кабинете или отправить Илье в Telegram для бесплатного разбора.

Для бизнеса это наглядная карта денег. Для Devlarion — лид, который пришёл с готовым брифом, понятным бюджетом и уже выбранным вариантом.

## Главные решения (не пересматривать без владельца)

1. **Сайт остаётся статическим.** GitHub Pages, ванильный JS, никаких npm-зависимостей и сборщиков. Ровно как в остальном репозитории: классические скрипты `defer`, IIFE, данные в `window.DevlarionGM`.
2. **Этап 1 работает без нейросети.** Варианты собирает детерминированный движок по правилам из каталога: мгновенно, бесплатно, без утечки данных и без риска, что ИИ придумает несуществующую услугу. Режим «Опишу своими словами» на этапе 1 разбирает текст локальным парсером по словарю и показывает заполненную форму для проверки.
3. **Этап 2 добавляет ИИ поверх движка** (файл 07). Нейросеть выбирает блоки только из каталога и пишет пояснения, а все цифры по-прежнему считает движок. Включается одной строкой в `content/site.json`. Если ИИ недоступен, сайт молча возвращается к движку.
4. **Цифры оптимистичные, но правдоподобные.** Эффекты блоков заданы с запасом в пользу продажи, но общий прирост ограничен потолками по варианту (см. 04-engine.md, раздел 5). Внизу сноска одной строкой: «Расчёт ориентировочный…». Без неё сайт уязвим по закону о рекламе, а продажам она не мешает.
5. **Названия вариантов без слов «дешёвый» и «дорогой»:** «Фундамент», «Ускорение», «Автопилот». Плюс состояние «Как сейчас», с которым всё сравнивается.
6. **Двуязычность.** Каждая страница существует в `ru/` и в корне (en), как весь сайт.
7. **Данные клиента остаются у клиента.** Схема хранится в `localStorage`, экспортируется файлом `.json` и ссылкой. На сервер ничего не уходит, пока человек сам не нажмёт «Отправить в Telegram» (или, на этапе 2, «Разобрать с ИИ» с явным согласием).

## Определение готовности этапа 1

- `npm run build` и `npm run check` проходят, CI зелёный.
- Страницы `/growth-map/` и `/ru/growth-map/` открываются, работают во всех четырёх темах (Авто, Медь, Тёмно-синяя, Шалфей) и при `prefers-reduced-motion`.
- Пять тестовых брифов из `06-integration.md` проходят `npm run test:gm`.
- Ручной прогон по чек-листу из `08-tasks.md` (десктоп Chrome и Safari, мобильный 375 px) пройден, скриншоты приложены к PR.
- В Lighthouse на странице карты нет ошибок доступности уровня «serious», консоль без ошибок.

## Что изменилось при реализации

Оформление пересобрано под стиль сайта: приглушённая палитра этапов вместо радужной, «семантический зум» (на обзорном масштабе у узлов остаются крупные названия, мелкий текст скрывается), сравнение вариантов карточками вместо широкой таблицы, панель справа сворачивается, на телефоне карта по умолчанию открывается списком, а блоки и сравнение идут обычной лентой под ней. Формулы, каталог и формат файла остались как в 03–04.
